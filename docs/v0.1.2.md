# The Pony Desktop v0.1.2：集成、升级与维护

本版本不修改窗口、鼠标、任务栏、绘图服务或输入算法。桌面仍单独编译为Ring 3应用，沿用v0.1.1图形ABI。

## 集成机制

`integration/apply.sh` 调用Python管理器。使用现有HoofTTY检出，不自动拉取、切分支、reset或修改Git索引。
基线对象必须存在：`8d2951186df48773d6014290f08be9ebf0df8257`。
管理器从该提交的受管理文件与已发布补丁在临时目录构造已知文件集，不依赖TPD本地Git历史。
随后逐字节验证实际接口文件集；只接受原始基线、完整v0.1.0/v0.1.1或当前接口。
旧版应用通过已发布源码SHA256识别，当前应用直接比较；未知应用修改、ABI变化、混合接口或受管理路径的符号链接均拒绝。

```sh
./integration/apply.sh /path/to/HoofTTY --check
./integration/apply.sh /path/to/HoofTTY
make HOOFTTY=/path/to/HoofTTY
```

`--check` 只读取检出，在临时目录构造计划，不写检出、不修改暂存区。
实际写入前先检查所有目标，再将待改文件备份到输出的 `/tmp/tpd-backup-*` 路径。
其中 `absent.json` 记录安装前不存在的路径；其他文件是安装前内容，按相对路径保存。
随后以同目录临时文件和rename逐文件替换，保留已有文件权限；普通Python异常触发回滚，备份保留。

这是逐文件更新，不是整个检出的原子事务。不要同时编辑受管理文件或并发运行安装器。
断电、SIGKILL、磁盘故障、回滚本身失败等不能保证自动恢复；此时先保全当前修改和备份，
逐项比较备份后恢复原文件，并移除absent.json中确认属于此次安装的新文件，再运行预检。
临时目录可能被系统清理，需要长期保留时请自行复制到持久目录。

未知本地修改不会自动三方合并，也不应使用reset绕过拒绝。请先自行备份、审阅并合并。
脚本保留受管理集合之外的文件及暂存区。历史补丁用于识别和生成目标，不要手工叠加应用。
v0.1.2只在v0.1.1内核接口基础上追加版本头的Make依赖，不新增系统调用。

## 版本维护

`VERSION` 是运行时版本唯一来源。`scripts/version.py --set X.Y.Z` 更新VERSION与README标题；
`make check-version` 检查二者一致，`make version` 显示版本。
集成器生成 `apps/tpd_version.h`，应用启动消息与任务栏复用TPD_VERSION。
生成格式完整且版本不高于目标的旧版本头可升级，未知头或降级会被拒绝。
`$(BUILD)/apps/tpd.elf: apps/tpd_version.h` 保证仅更改版本头也触发重编译。
没有新增v0.1.2内核大补丁，沿用已发布接口文件集，避免仅为版本号复制整份补丁。

源码包自带旧版应用回归夹具和校验值；测试及安装均不要求TPD历史提交存在。
未来若改变内核接口，需要扩展已知接口配置及测试，不应简单修改旧版补丁内容。
