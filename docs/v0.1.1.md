# v0.1.1 — 图形刷新与输入修复

基于 v0.1.0 提交9cbd07a及同一 HoofTTY 基线；不增加桌面组件，不移动窗口逻辑到内核。

原因：原应用直接在可见 framebuffer 依次清背景、绘制窗口和光标，每次拖动都会暴露中间背景。
用户只有4 KiB代码/栈，不能容纳屏幕副本。新版本使用内核静态3 MiB后备缓冲，应用仅追加begin/present调用。
驱动累积脏包围盒，并比较最终颜色后写回，避免清屏中间态以及未变化像素的显存写入。
这牺牲固定内核保留空间，换取不引入动态多页分配/回收路径；限制最高1024×768，错误时恢复Shell。
用户态仍会重绘全场景，CPU侧不是完整脏矩形渲染器；无垂直同步，不能承诺所有后端无撕裂。

PS/2：保持1:1缩放，显式请求200Hz采样；共享端口每次最多排空256字节，较旧版32字节降低积压。会话内启用AUX IRQ12及时分流数据，退出恢复控制器与PIC屏蔽值。
输入不再先取坐标再睡眠；保留按钮边沿，连续同按钮移动合并为最新位置，避免移动队列延迟。
有限队列溢出仍会丢旧记录；鼠标硬件/QEMU在送达之前合并的短点击无法由此恢复。

QEMU绝对指针评估：现有客户机只有i8042驱动。添加 `-device usb-tablet` 不会自动使其工作，需USB主机控制器及HID驱动；
virtio-input也需PCI/virtqueue及新输入驱动。这些单列后续工作，本版不启用无法消费的设备。
使用QEMU鼠标抓取（通常Ctrl+Alt+G，具体以后端为准）可改善相对指针操作；宿主加速、缩放、边界夹紧仍可能造成视觉偏差。
不宣称PS/2软件光标等同宿主绝对坐标。

快速移动回归最初在纯轮询实现中失败（窗口未到达预期坐标），保留失败记录；改用会话内IRQ12后重跑。

## 验证与范围

实际QEMU/TCG、128MiB、标准VGA、SeaBIOS、800×600，脚本见 tests/qemu_smoke.py。
结果与截图保存在 evidence/v0.1.1；旧 evidence 顶层是v0.1.0历史记录。
连续拖动测试40次交替相对移动，采样检查窗口重叠区域没有变为背景；短促20ms点击关闭窗口。
三次进出、Q/任务栏退出、Shell回应、hello及privileged故障隔离、GDB用户态证据及资源计数均检查。
宿主测试新增未present前显存保持不变、重复begin拒绝、提交/退出状态检查，保留裁剪和canary测试。

自动截图是离散样本，未进行真人观看连续视频、不同显示后端/宿主缩放/硬件测试；未证明完全消除闪烁。
未验证USB/HID、绝对坐标、鼠标拔除或极端队列溢出；不承诺无丢事件。
旧上游test-host缺失help.c问题未修改，完整上游多配置测试矩阵未运行。

最终回归通过：连续40次移动及短点击后关闭窗口，三次退出后的 allocated=16、tables=5、mapped=16 均回到基线。
静态缓冲使可用物理页总数较v0.1.0减少约3MiB，这是固定内核保留，不是反复进入造成的泄漏。
用户应用映像2122字节，仍小于4KiB。干净基线应用新补丁后内核构建及ELF检查通过。
