# 源码审计与最小路线

基线：HoofTTY `8d2951186df48773d6014290f08be9ebf0df8257`。以下先描述修改前实际源码，非依据教程推定。

| 能力 | 原有实现与证据 | v0.1.0 的处理 |
|---|---|---|
| 用户态 | `kernel/syscall/user.c` 的 `user_run/start`、`kernel/arch/x86_64/user-enter.S`；Ring 3 进入、调度、异常回收 | 复用，不新增桌面内核任务 |
| 加载 | `Makefile` APPS→ELF→bin→apps.S；`user_run` 的 PICK 白名单、大小检查、复制与映射 | 增加 tpd 白名单，保留 4 KiB 限制；不实现通用 ELF |
| 显示 | `kernel/drivers/framebuffer.c` 验证 Limine RGB32 布局、终端及精灵绘制 | 新增裁剪矩形/字形服务、会话期间暂停终端像素输出 |
| 鼠标 | 原 `keyboard_init` 明确禁用 AUX；IRQ 输入拒绝 AUX；没有鼠标驱动/事件分发 | 会话内启用 PS/2 流，解析三字节包，轮询并复用 IRQ1 排空共享端口 |
| 服务 API | `apps/abi.h` 与 `syscall_dispatch`：write/uptime/yield/exit，检查调用 CPL、任务身份与用户范围 | 追加 4–8 号服务，无用户指针传入新服务 |
| Shell 启停 | `shell/commands/run.c`→`user_run` 等待 `user_state.active` 清除；`user_reap` 释放页 | `run tpd`；正常释放和任务回收都调用会话清理，恢复后原 Shell 打印提示符 |

原系统可以运行受限用户程序，但不能运行独立图形应用：缺少用户绘图和输入 API、鼠标驱动与显示所有权。
最低可行路线是增加这些内核基础服务，然后在既有用户态加载机制中运行 TPD。
没有大规模重构调度/内存/中断系统，没有将桌面函数编入内核并由 Shell 调用。

## 平台层

新 `graphics.c` 仅管理一个显示会话、PS/2 数据包与坐标、服务调用；`framebuffer.c` 保持设备布局验证，
绘图按实际 pitch 和 RGB 通道位置写像素，所有矩形/字形在可用屏幕内裁剪。
IRQ12 保持屏蔽，避免改变现有 PIC 路由。输入调用每 tick 轮询；IRQ1 同样分流 AUX 字节，避免混入键盘扫描码。
这些端口操作在内核、关中断上下文中执行，等待有上限。鼠标初始化失败关闭 AUX 并拒绝接管显示。
丢弃鼠标 overflow 包，并检查同步位；不支持热插拔、扩展鼠标包和复杂错误恢复。

Shell 等待唯一用户任务结束，所以图形会话与交互式 Shell 不争抢输入。串口输出继续工作，便于调试。
应用状态保存在用户栈；没有堆分配、文件、网络或宿主 GUI 依赖。
显示服务不暴露内核地址，不扩展用户可写内存；用户退出仍走既有调度/页回收流程。
`user_reap` 无条件尝试释放显示会话，避免故障任务永久占用显示。
本轮测试证明了正常退出回收；图形任务故障时的恢复路径尚未注入验证。

## 明确不具备的能力

没有磁盘安装、通用 ELF/PT_LOAD、独立进程 CR3、动态链接、运行时模式切换、保存终端屏幕历史、USB 鼠标、窗口服务器。
内嵌映像解决当前 OS 的分发限制，但最终外部独立软件目标仍需 OS 侧通用加载基础设施。
